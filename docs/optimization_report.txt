三、具体改进内容
============================================================

### Developer Prompt (src/agent.py)

1. **THINKING思考流程**: 每轮必须执行的三问框架 (目标分析→工具选择→参数构造)
2. **角色定义**: "你是一个任务执行Agent。你的唯一职责是..."
3. **核心行为准则**: 4条分层规则 (只做一件事/绝不输出计划文本/写实际代码/合并操作)
4. **工具选择策略**: 按场景路由 (计算→python_exec, 读写→file_io, 搜索→search)
5. **错误处理**: 明确重试策略 (最多2次, 失败报告)
6. **正反例对比**: 3组具体示例

### Decompose Prompt (src/planner/llm_planner.py)

1. **SMART-E标准**: 具体+可执行+有数据流+逻辑有序
2. **复杂度分级**: 简单(不分解)→中等(线性)→复杂(分阶段)
3. **好坏分解对比**: 具体示例说明什么是好步骤
4. **THINKING框架**: 5步内部推理 (交付物→里程碑→工具→风险→合并)
5. **结构化输出**: 含complexity字段
6. **中文指令**: 降低LLM理解偏差

### Evaluate Prompt (src/planner/llm_planner.py)

1. **三维度评估**: 正确性→完整性→实现性
2. **决策矩阵**: 6种情况→对应行动
3. **replan策略**: 4种触发条件 (错误修复/方法转换/范围调整/跳过补偿)
4. **进度跟踪**: 连续失败计数 (3次失败终止)
5. **关键判断规则**: 计划文本检测、步骤耗尽处理
6. **示例**: 3个典型场景

五、从OPUS-5.md提取的最佳实践
============================================================

1. 分层指令架构 (XML标签分层)
2. 思维链引导 ("think before it answers")
3. 正反例对比 (每个重要规则都有RIGHT/WRONG)
4. 质量自检 (输出前自检)
5. 安全分层防护 (输入→处理→输出)
6. 上下文感知决策 (丰富的上下文)
7. 错误处理与降级 (预定义错误类型)
8. 渐进式复杂度 (根据任务调整深度)
9. 格式一致性 (统一输出格式)
10. 角色锚定 (多处强化角色定义)
