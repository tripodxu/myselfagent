## 一、参考提示词分段结果

### 第1段: 核心身份与行为规范
- **位置**: <claude_behavior> 标签内
- **内容**: 产品信息、身份定义、能力边界
- **关键技巧**: 
  - 明确定义"我是谁"和"我能做什么"
  - 产品信息作为背景知识而非行为指令
  - 使用XML标签结构化不同行为域
- **重要性**: ★★★★★ 核心基础

### 第2段: 思维链与推理规范
- **位置**: <thinking_behavior> 标签
- **内容**: 鼓励深度思考、不急于回答、复杂问题开extended thinking
- **关键技巧**:
  - "Even for questions that might seem obvious, if there are any signs of lurking complexity, Claude takes the time to open up an extended thinking block"
  - 要求在思考结束时重申应使用的语言
  - 思考过程与输出分离
- **重要性**: ★★★★★ 决定推理质量

### 第3段: 工具使用规范
- **位置**: <available_skills> 和工具相关指令
- **内容**: 技能注册、工具选择策略、工具调用格式
- **关键技巧**:
  - 技能通过描述+触发条件注册
  - 工具调用有明确的前置条件检查
  - 技能优先级和冲突解决机制
  - 工具输出的处理和截断策略
- **重要性**: ★★★★★ Agent核心能力

### 第4段: 安全与伦理约束
- **位置**: 分散在多个标签中
- **内容**: 内容安全、代码安全、隐私保护、伦理边界
- **关键技巧**:

- **重要性**: ★★★★☆ 输出质量保障

## 二、当前项目提示词问题诊断

### 提示词1: Agent._build_messages() Developer Prompt
**位置**: src/agent.py 第100-120行

**问题诊断**:

1. **角色定义模糊** (严重度: 8/10)
   - 只说"You are an AI agent that EXECUTES tasks by WRITING CODE"
   - 缺少: 你是谁、你的能力边界、你的行为准则
   - 对比OPUS-5: Claude有完整的产品信息、能力描述、行为规范

2. **规则缺乏层次** (严重度: 7/10)
   - 6条CRITICAL RULES平铺，无优先级
   - 缺少: 规则间的逻辑关系、冲突时的处理策略
   - 对比OPUS-5: 使用XML标签分层，每层有明确的作用域

3. **正反例不够具体** (严重度: 6/10)
   - WRONG/RIGHT各只有一个例子
   - 缺少: 多种场景的示例、边缘情况的处理
   - 对比OPUS-5: 每个重要规则都有详细的正反例

4. **缺少思维链引导** (严重度: 9/10)
   - 直接要求输出JSON，没有引导LLM先思考
   - 缺少: 分析目标→选择工具→构造参数的推理过程
   - 对比OPUS-5: "think before it answers"，鼓励深度思考

5. **错误处理指引缺失** (严重度: 7/10)
   - 没有告诉LLM执行失败时怎么办
   - 缺少: 重试策略、降级方案、错误报告格式
   - 对比OPUS-5: 有完整的错误处理和降级策略

6. **上下文利用不充分** (严重度: 6/10)
   - user message只包含goal、step、prior_results
   - 缺少: 工具历史调用结果、失败原因、进度信息
   - 对比OPUS-5: 丰富的上下文信息帮助决策

## 三、从OPUS-5.md提取的Agent系统最佳实践

### 实践1: 分层指令架构 [关键]
**来源**: OPUS-5的XML标签结构
**技术**: 使用多层标签组织指令，每层有明确的作用域
**应用**: 
- system prompt分为: 角色层 → 行为层 → 工具层 → 安全层 → 格式层
- 每层内部使用有序列表，层间使用XML标签分隔
- 高优先级指令放在更外层标签

### 实践2: 思维链引导 [关键]
**来源**: <thinking_behavior> 标签
**技术**: 要求LLM先思考再回答，复杂问题使用extended thinking
**应用**:
- 在输出JSON前要求LLM先分析目标
- 引导LLM思考: 目标分析 → 工具选择 → 参数构造 → 结果预期
- 思考过程不出现在最终输出中

### 实践3: 正反例对比 [关键]
**来源**: 分散在多个行为规范中
**技术**: 每个重要规则都用正例(RIGHT)和反例(WRONG)说明
**应用**:
- 决策prompt: 正确的JSON格式 vs 常见错误格式
- 代码生成: 可运行的代码 vs 计划文本
- 评估: 真正完成 vs 表面完成

### 实践4: 质量自检机制 [关键]
**来源**: thinking_behavior 和评估指令
**技术**: 要求LLM在输出前自检，不确定时降级
**应用**:
- 决策前: 检查工具选择是否合理
- 执行后: 检查输出是否符合预期
- 评估时: 多维度验证结果质量

### 实践5: 安全分层防护 [关键]
**来源**: 安全相关指令
**技术**: 输入层→处理层→输出层的多层安全检查
**应用**:
- 输入层: 危险模式检测
- 处理层: 权限边界检查
- 输出层: 内容安全审查

### 实践6: 上下文感知决策 [重要]
**来源**: 上下文管理指令
**技术**: 基于丰富的上下文信息做出更好的决策
**应用**:
- 传递: 当前目标、已完成步骤、失败原因、成功模式
- 压缩: 旧信息摘要，新信息完整
- 优先: 系统消息 > 最近消息 > 历史摘要

### 实践7: 错误处理与降级 [重要]
**来源**: 错误处理相关指令
**技术**: 预定义错误类型，每种有明确的处理策略
**应用**:
- 工具调用失败: 重试 → 换工具 → 报告
- 输出格式错误: 解析 → 修复 → 降级
- 目标无法完成: 分析原因 → 调整策略 → 用户确认

### 实践8: 渐进式复杂度 [重要]
**来源**: 任务分解策略
**技术**: 根据任务复杂度调整行为深度
**应用**:
- 简单任务: 直接执行，减少开销
- 复杂任务: 分解→规划→逐步执行→验证
- 不确定任务: 先探索再决策

### 实践9: 格式一致性 [重要]
**来源**: 输出格式控制
**技术**: 统一的输出格式，便于下游处理
**应用**:
- JSON输出: 固定结构，必填字段
- 错误报告: 统一格式
- 进度反馈: 结构化信息

### 实践10: 角色锚定 [重要]
**来源**: 角色一致性要求
**技术**: 在多个位置强化角色定义，防止角色漂移
**应用**:
- 开头定义角色
- 每次决策前重申核心规则
- 关键场景强化角色约束
